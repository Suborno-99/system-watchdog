System Watchdog & Auto-Healer

Running in Background

Modular, pluggable system health monitoring, debounced timers, and auto-recovery.

📁 Modular Architecture

The watchdog is fully structured into pluggable checks and actions. You can add new features by simply dropping a script into checks/ or actions/.

~/.config/system-watchdog/ ├── config.conf # Timing (4s check, 4s delay), ping endpoints, toggles ├── watchdog # CLI manager (status, test, start, stop, new) ├── checks/ # Health check scripts (*.sh) │ ├── 10-internet.sh # [Active] Ping DNS/Gateway + NetworkManager check │ └── 20-docker.sh.example # [Example] Check docker service & containers ├── actions/ # Recovery actions (*.sh) │ ├── 10-reconnect-network.sh # [Active] Auto-reconnect profile / bounce interface │ ├── 20-notify.sh # [Active] Cinnamon desktop notification │ └── 30-custom-command.sh.example ├── templates/ # Templates for scaffolding new features └── logs/watchdog.log # Live logs & history

🚀 How to Add More Features in 2 Minutes

Want to monitor a new service, an API endpoint, a VPN, or run a custom recovery script? Follow these simple steps:

Step 1: Create a New Health Check

Run the scaffolding command in terminal:

watchdog new check my-api

Edit ~/.config/system-watchdog/checks/my-api.sh to test your service:

check_name="My API Health"
check_description="Verifies API on port 3000 is responding"

check_run() {
    curl -sf http://localhost:3000 >/dev/null 2>&1
    return $?  # Return 0 if healthy, non-zero if failing
}

Step 2: Test Your Check Immediately

watchdog test

You'll see a green PASSED or red FAILED badge for all your checks!

Step 3: (Optional) Add a Custom Recovery Action

If you want a specific recovery action (like restarting a service, flushing cache, or sending a webhook):

watchdog new action restart-my-service

Edit ~/.config/system-watchdog/actions/restart-my-service.sh:

action_name="Restart Web Service"

action_run() {
    local failed_check="$1"
    watchdog_log "Healing triggered for: $failed_check"
    # Example: systemctl --user restart my-service
    # Example: docker restart my-container
    return 0
}

🛠️ Command Line Reference

Command Description
watchdog status (or net-status) Shows running status (PID), active modules, and recent logs.
watchdog test Runs all health checks right now and displays PASS/FAIL.
watchdog reconnect (or reconnect) Triggers network/recovery actions immediately without waiting.
watchdog list Lists all installed checks and actions.
watchdog logs Streams live log output (tail -f).
watchdog restart Restarts the daemon (reloads configuration and new modules).
watchdog new check <name> Scaffolds a new health check script.
watchdog new action <name> Scaffolds a new recovery action script.
